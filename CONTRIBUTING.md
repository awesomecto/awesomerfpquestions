# Contributing to Awesome RFP Questions

Thank you for your interest in contributing to this collection! This guide will help you submit high-quality RFP questions.

## How to Contribute

There are two ways to submit RFP questions:

### Option 1: Submit via GitHub Issue (Recommended for New Contributors)

1. Go to the [Issues](../../issues) tab
2. Click "New Issue"
3. Select "Submit RFP Question"
4. Fill out the template with your question details
5. Submit the issue

A maintainer will review your submission and create a pull request to add it to the repository.

### Option 2: Submit via Pull Request (For Advanced Contributors)

1. Fork this repository
2. Create a new branch for your question
3. Add a new markdown file in the `questions/` directory
4. Follow the naming convention: `category-brief-description.md`
5. Use the format specified in [TEMPLATE.md](TEMPLATE.md)
6. Submit a pull request

## Question Format

Each question file must include:

### Front Matter
```yaml
---
category: [Your Category Name]
---
```

### Question Section
The actual RFP question being asked.

### Good Response Section
An example or description of what constitutes a good response. This should help both respondents and evaluators understand what's expected.

### What to Look For Section
Key points that evaluators should look for when reviewing responses. This helps ensure consistent evaluation.

## Best Practices

### Writing Questions
- **Be specific**: Avoid vague or overly broad questions
- **Be relevant**: Ensure the question is commonly asked in RFPs
- **Be clear**: Use clear, professional language

### Writing Good Responses
- **Provide examples**: Include concrete examples when possible
- **Be comprehensive**: Cover all important aspects
- **Show depth**: Demonstrate what separates good from great responses

### Writing Evaluation Criteria
- **Be objective**: Focus on measurable or observable criteria
- **Be thorough**: Cover all important aspects to evaluate
- **Be practical**: Ensure criteria can be realistically assessed

## Categories

Common categories include (but are not limited to):
- Technical Architecture
- Security
- Financial/Pricing
- Project Management
- Team/Staffing
- Support/Maintenance
- Compliance/Legal
- Performance/Scalability

Feel free to suggest new categories if your question doesn't fit existing ones.

## Review Process

1. All submissions are reviewed by maintainers
2. Feedback may be provided for improvements
3. Once approved, questions are merged and the README is automatically updated
4. The GitHub workflow will regenerate the questions table

## Questions?

If you have questions about contributing, please open an issue with the "question" label.

## Code of Conduct

Please be respectful and professional in all interactions. We aim to maintain a welcoming and inclusive community.
